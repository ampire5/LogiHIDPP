# Заметки об устройстве: MX Master 4 на приёмнике Bolt

Записано 2026-10-16 на мыши пользователя (`logi-probe raw` + временный перехват). Байты — в
`Tests/LogiHIDPPTests/Fixtures.swift`.

## Устройство

- Приёмник Bolt `046d:c548`, служебный интерфейс — страница `0xFF00`, usage 1; мышь на месте 2, HID++ 4.5, 46 функций.
- Номера функций: `0x1B04` → 13, `0x19B0` → 11, `0x2150` → 19 (`0x13`), `0x2121` → 18 (`0x12`), `0x1004` → 9.

## Колесо под пальцем (`0x2150`)

- Функция 0 (info): `00 14 00 78 00 03 03 e8` — 20 шагов на оборот без перехвата, 120 с перехватом, направление по
  умолчанию 0, возможности `0x03` (отметка времени, касание), единица времени 1000 мкс.
- Функция 2 (set reporting): `01 00` — перехват, `00 00` — вернуть системе. Ответ — пустые параметры. Функция 1
  (status) возвращает `00 00` и до, и после перехвата — состояние по ней не определить.
- Уведомление (функция 0): поворот Int16 BE (±1 на событие при 120/оборот), время с прошлого события UInt16 BE в мс,
  состояние (0 — нет, 1 — начало, 2 — вращение, 3 — конец), флаги (бит 1 — палец на колесе). Касание без поворота:
  событие с поворотом 0 и флагом `02`, снятие пальца — с флагом `00`. Конец вращения (`03`) приходит без флага касания.
- После выключения мыши перехват сбрасывается (проверено косвенно: мышь заново конфигурируется другими клиентами,
  см. ниже).

## Колесо высокого разрешения (`0x2121`, Precision Scroll)

Замеры FrameScrub 2026-10-15 и чтение пакетом
2026-10-18 (`logi-probe hires`: `0x2121` под индексом 18, режим `0x00`).

- `0x2121` под индексом 18 (`0x12`), множитель 15; функция 1 (getWheelMode) → байт режима, по умолчанию `00`;
  функция 2 (setWheelMode) пишет байт режима. Бит 0 — divert (перехват колеса), бит 1 (`0x02`) — высокое
  разрешение, бит 2 — invert. Ответ на запись пакетом не проверяется (без эха): его формат на мыши не записан.
- Через macOS без перехвата: выключен — щелчок даёт одно событие, 5 щелчков — 5, 10 подряд — 10, меньше щелчка — ни
  одного; включён — ~6 событий на щелчок, 32, 62, лёгкое касание — одно. Величины событий macOS разгоняет, надёжен
  только счёт событий. С режимом прокрутка списков в других программах разгоняется примерно в 400 раз — поэтому
  только пока нужно.
- Переподключение мыши (уведомление `0x41`, пробуждение Mac) сбрасывает режим в мыши.
- BetterMouse (метка программы 8) после каждого переподключения пишет в функции 9, 18 и 20 (см. «Подключение мыши»):
  то есть и в `0x2121` — режим надо перечитывать после переподключения.

## Подключение мыши

- Выключение: `10 02 41 10 42 42 b0`; включение: `10 02 41 10 02 42 b0`. Байт 4, бит 6 — связь потеряна. Уведомления
  приходят без включения регистра уведомлений: приёмник уже шлёт их (вероятно, их включил другой клиент).
- Через ~5 мс после каждого — `10 ff 8f 83 b5 0b 00` (ошибка приёмника на чужой запрос) и, после включения, поток
  запросов с меткой программы 8 (BetterMouse перенастраивает мышь: функции 9, 18, 20). Наш канал их игнорирует.

## Другие клиенты на приёмнике

BetterMouse (метка программы 8) и что-то, что раз в несколько секунд читает регистры приёмника (`10 ff 81 …`,
`11 ff 83 fb …`). Перехват кнопок и колеса BetterMouse не трогает.

## Вибрация `0x19B0` (2026-10-16, вторая сессия)

- Функция 0 (возможности): `00 01 00 3c 08 00 7f ff`; байты 4–7 — маска узоров `0x08007FFF`: узоры `0x00…0x0E` и
  `0x1B` (Whisper collision) — всего 16. Номера и имена — Logitech, по Solaar (`hidpp20_constants.HapticWaveForms`).
- Функция 1: `01 19` — включена, сила 25; байт 2 = 0 — мышь принимает любую силу 0–100 (бит 0 = 1 означал бы только
  25/50/75/100).
- Функция 2 пишет `включена сила`: `01 19` принято и прочитано обратно; по просьбе пользователя поставлено `01 23`
  (сила 35), прочитано `01 23`. Пакет пишет силу только по просьбе приложения.
- `logi-probe haptic whisper-collision` (через пакет) — сыграл.

## Сильный узор и сила нажатия панели (2026-10-16, третья сессия)

- `0x19C0` (номер 12): функция 0 → `01` (одна кнопка); функция 1 `00` → `00 01 12 8d 18 ac 0e d7` (изменяемая,
  по умолчанию 4749, макс 6316, мин 3799); функция 2 `00` → `12 8d`; функция 3 `00 0e d7` записала 3799 (самое
  лёгкое, по просьбе пользователя), прочитано `0e d7`.
- Сильный узор через пакет (`logi-probe haptic sharp-collision 80` при обычной 35): запись силы и узор подряд без
  ожидания ответов, сразу возврат к 35 — пользователь: узор полный и заметно сильнее; после — сила 35.

## Наблюдение за кнопками (analytics key events), 2026-10-16

Нужно, чтобы слушать кнопки назад / вперёд, не забирая их у Mac Mouse Fix (он перехватывает их сам). Проверено на
мыши отдельной одноразовой утилитой при работающем Mac Mouse Fix: приходили все нажатия и отпускания назад / вперёд,
около 40 событий, ни одно не потеряно. Код пакета (`LogiMouse.watch`) этой сессией на живой мыши не запускался.

- `getControlInfo` (функция 1), байт 8 («flags2»): назад `0x53`, вперёд `0x56`, средняя `0x52`, `0xc3`, `0xc4`,
  панель `0x1a0` → `0x05`; левая и правая `0x50`, `0x51` → `0x04`; `0xd7` → `0x03`. Бит `0x04` — события аналитики
  поддерживаются (у Solaar `KeyFlag.ANALYTICS_KEY_EVENTS = 0x400` над 16-битными флагами = байт 4 | байт 8 << 8);
  бит `0x01` — сырые XY.
- `setControlReporting` (функция 3), параметры `cid_hi cid_lo 00 00 00 03` включают аналитику (байт 5: бит 0 — включить,
  бит 1 — значение действительно; байт 2 = 0 не трогает флаги перехвата, переназначение 0 = без изменений);
  `… 02` выключает. Ответ и `getControlReporting` (функция 2) показывают байт 5 = `01` (включена) / `00` (выключена).
  Запрос длиннее трёх параметров: длинный отчёт (`0x11`).
- События: уведомление функции **2** признака `0x1B04`, параметры `cid_hi cid_lo состояние` (1 — нажата, 0 — отпущена),
  например `00 56 01 00 00 …`, затем `00 56 00 00 00 …`. Пакет читает до пяти подряд идущих троек (cid, состояние) до
  первого нулевого CID (Solaar разбирает список; мы видели только одну тройку).
- При включённой аналитике ОС по-прежнему получала кнопку (Mac Mouse Fix на неё реагировал); колесо при зажатой
  наблюдаемой кнопке доходило до приложений обычной построчной прокруткой.
- Решение в пакете: контрол в наборах `divert` и `watch` одновременно только перехватывается (перехват побеждает).

## SmartShift (`0x2111`), 2026-10-18

Проверено на мыши пользователя (`logi-probe smartshift`, `watch c4`, `raw`), FrameScrub работал.

- `0x2111` (SmartShift enhanced) под индексом 17 (`0x11`); `0x2110` нет.
- Функция 0 (возможности): `01 0a 4b 0e` — бит 0: усилие настраивается; порог автопереключения по умолчанию 10,
  усилие по умолчанию 75, `0x0e` — максимум силы (по Solaar).
- Функция 1 (режим): `02 0c 4b` — режим (`01` свободное вращение, `02` трещотка), порог автопереключения 12, усилие 75.
- Функция 2 (запись): параметры `режим порог усилие`, `0` — не менять. `01 00 00` → ответ `01 0c 4b` (эхо всего
  режима), читается `01 0c 4b`; `02 00 00` вернул трещотку. Порог и усилие не тронуты.
- Кнопка SmartShift (`0xC4`, flags2 `05`) наблюдается без перехвата: `11 02 0d 20 00 c4 01` / `… 00` (нажата /
  отпущена), ~150 мс между ними; мышь при этом сама переключает режим, и функция 1 его показывает (4 нажатия:
  `02 → 01 → 02 → 01 → 02`). Своего уведомления у `0x2111` нет: режим после нажатия надо прочитать.
